# Parfum · Turnover Terminal

Веб-дашборд оборотності парфумів на OLX.ua. Знімає каталог щодня; коли *молоде*
оголошення зникає — вважає це продажем (застаре для експірації). Показує бренди,
відсортовані за реальним попитом: скільки розійшлось, як швидко, за скільки.

Стек: Node + Express + SQLite (better-sqlite3) + node-cron. Фронт — статичний,
без збірки. Готовий під Railway.

---

## Локальний запуск
```bash
npm install
cp .env.example .env          # впиши свої category_id
OLX_CATEGORY_IDS=1665,1666 CRAWL_ON_START=1 npm start
# відкрий http://localhost:3000
```

## Як дізнатись category_id
1. Відкрий категорію парфумів на olx.ua (жіноча / чоловіча — ID різні).
2. DevTools → **Network** → фільтр `offers` → онови сторінку.
3. У запиті до `/api/v1/offers/` візьми `category_id`.

Обидві категорії можна крутити разом: `OLX_CATEGORY_IDS=1665,1666`. У дашборді
буде фільтр по категорії.

## Деплой на Railway

1. **Залий код у GitHub** (приватний репозиторій — ок).
2. Railway → **New Project → Deploy from GitHub repo** → обери репо.
   Nixpacks сам підхопить Node і `npm start`.
3. **Variables** (вкладка Variables сервісу) — додай:
   ```
   OLX_CATEGORY_IDS = 1665,1666
   OLX_DB           = /data/olx.db
   ADMIN_TOKEN      = <будь-який секрет>
   TZ               = Europe/Kyiv
   CRAWL_ON_START   = 1        # тільки на перший деплой, потім прибери
   ```
4. **Volume** (щоб дані не злітали): у сервісі → **+ Volume** → mount path `/data`.
   Саме тому `OLX_DB=/data/olx.db`. Без волюма БД обнуляється при кожному редеплої.
5. **Generate Domain** (Settings → Networking) — отримаєш публічний URL.
6. Відкрий URL, тисни **«Зібрати зараз»**. Далі краул сам ходить щодня о 09:00
   (Київ). Оборотність зʼявиться після **другого** дня.

> Порада: після першого успішного краулу прибери `CRAWL_ON_START`, щоб сервіс не
> краулив на кожному рестарті.

## Змінні оточення

| Змінна             | Обовʼязк. | Дефолт          | Що робить |
|--------------------|:---------:|-----------------|-----------|
| `OLX_CATEGORY_IDS` | так       | —               | ID категорій через кому |
| `OLX_DB`           | на Railway| `./data/olx.db` | шлях до БД (став `/data/olx.db` + Volume) |
| `ADMIN_TOKEN`      | бажано    | —               | захищає кнопку/ендпоінт краулу |
| `CRAWL_SCHEDULE`   | ні        | `0 9 * * *`     | cron розкладу |
| `TZ`               | ні        | `Europe/Kyiv`   | таймзона крону |
| `OLX_REGION_ID`    | ні        | (вся Україна)   | звузити збір по регіону |
| `CRAWL_ON_START`   | ні        | `0`             | `1` = краул при старті |
| `PORT`             | ні        | 3000            | Railway підставляє сам |

## API
- `GET /api/status` — краули, кількості, міста, категорії.
- `GET /api/analyze?maxAge=21&minSold=2&city=&type=&categoryId=` — рейтинг.
- `POST /api/crawl` — ручний краул (заголовок `x-admin-token`, якщо заданий).

## Якщо білд на Railway падає
Причина майже завжди — Nixpacks бере надто нову Node (напр. 24), під яку в
`better-sqlite3` ще немає готового бінарника, і він падає в компіляцію без
компілятора в образі.

Фікс уже в репо: `engines.node = "22.x"` у `package.json` + файл `.nvmrc` (`22`).
Node 22 має prebuild — компіляція не потрібна. Переконайся, що обидва закомічені.

Якщо все одно бачиш у логах `node-gyp` / `prebuild-install` і фейл — додай у
корінь файл `nixpacks.toml`, щоб покласти в образ інструменти збірки:
```toml
[phases.setup]
nixPkgs = ["nodejs_22", "python3", "gcc", "gnumake"]
```

## Що памʼятати
- **Оборотність = кілька днів даних.** Один краул нічого не покаже. Мінімум 2
  знімки в різні дні, стабільно — ~2 тижні.
- **`lib/brands.js` — головний важіль точності.** Дописуй бренди/кирилицю/дюпи
  своєї ніші; нерозпізнане не потрапляє в аналіз.
- **Продаж — це проксі**, не факт: молоде оголошення могли зняти й не через
  продаж. Дивись медіани по бренду, не поштучно.
- **Пагінація OLX** ріже глибоку видачу (~1000). Скрипт не рахує зниклим те, що
  просто не догорнув. Для повного покриття великих категорій — сегментуй.
- **Ввічливість:** пауза 700мс між сторінками, нормальний User-Agent. Це
  внутрішній API, не офіційний — для особистого ресерчу ок, не влаштовуй ддос.
